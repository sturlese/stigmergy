# entities — the rules an identity is born under

The librarian WRITES every entity page (`librarian.identity`, inside the commit that files the
capture). This package is the pure rules that birth has to satisfy — the name gate, the collision
fold, the body builder, the page render — and the generator that derives
`ops/entity-registry.json` from the pages. Nothing here runs in a worker, on a poll, or behind an
agent, and **nothing here writes to git**: it answers questions and renders text, and
`librarian.identity` does the writing.

**The capture is the approval**.
An entity page's `approved_by:` names the person whose capture introduced the identity and is
never empty; a spelling the material uses for a registered entity is one of its `aliases:`. There
is no proposed state, no inbox and no decision — which is why this package has no CLI, no clone
and no door.

Three properties:

- **resolve before writing** — a colliding id/name/alias is refused at the gate, naming the entry;
- **the registry is a pure function of `wiki/entities/*.md`**, regenerated by the worker in the
  same commit as any page that changes one (`compare` makes a drift falsifiable, and
  `stigmergy-index --check` is where an operator sees one);
- **"who introduced this identity" is always answerable with a person** — `approved_by:` on the
  page, carried into the registry entry, both written by the commit that filed their capture.

## Modules

| Module | What it is |
|---|---|
| `birth.py` | resolve-before-write as a pure function of a proposal and a registry (`prepare`, `recheck`, `_refuse_collisions`), the terminal name gate every birth passes (`_clean_name`, `clean_aliases`, `_refuse_control_characters`), the body builder (`prepare_body`, with `EntityBody` and its per-field ceilings) and the page renderer (`render_page`, `_yaml_str`), plus the section names the body fills (`SUMMARY_SECTION` = `What / Who`, `FACTS_SECTION`, `CONNECTIONS_SECTION`). `render_page` REFUSES a body with no What / Who paragraph, drops a section it was given no lines for heading and stub together, and strips the template's HTML comments (`_strip_comments`). `approved_by` and `related` are arguments: the submitter's identity, and the page their capture filed |
| `generator.py` | the registry generator: `read_entity_pages` (each page's `PageEntity`, carrying `approved_by`), `derive_registry`, `registry_of`, `compare` (semantic drift, the approver included), `check` / `regenerate`, `canonical_id_for`, and the layout constants every other package spells through it (`ENTITIES_RELDIR`, `REGISTRY_RELPATH`, `TEMPLATE_RELPATH`, `APPROVED_BY_KEY`, `ENTITY_TYPES`, `FIX_COMMAND`). `FIX_COMMAND` is a SENTENCE, not a command: a drift is the worker's to regenerate away, and neither side is hand-edited |
| `errors.py` | `EntityError` (base — a declared identity this gate will not write) and `CollisionError` (the governance verdict: it already exists). Two classes because `librarian.identity` catches them SEPARATELY: the first becomes a finding naming the field, the second one naming the entity to anchor to instead. The clone-era classes went with the clone |

## Use these

- `birth.prepare` / `birth.recheck` — resolve-before-write, pure (a `Registry` in, a `Proposal` or
  a raised `CollisionError` out). `recheck` is the SAME `_refuse_collisions` asked again after a
  rebase, against a registry that may have moved under the run.
- `birth.prepare_body` / `birth.render_page` — the body's shape and the page's bytes. The template
  is read from the knowledge repo and never reproduced here, so an edit to it reaches new pages
  with no platform release.
- `generator.read_entity_pages` / `derive_registry` / `registry_of` — the registry as a pure
  function of the pages. `registry_of` takes a page list so a caller can ask what the repo implies
  MINUS the entity being born; `derive_registry` is the whole-repo answer.
- `generator.compare` / `check` — every way the pages and the committed registry disagree, each
  named in the words a reader acts in. Read-only, safe on a dirty clone and in CI.
- `generator.canonical_id_for` — the id a page titled `name` will always regenerate as. `slugify`,
  never `normalize`: an id is a stable file-safe handle, not the alias matcher's fold.

## Avoid

- **Writing to git from here.** This package renders and judges; `librarian.identity` writes,
  inside the gated commit that files the capture, and that is the only writer of `wiki/entities/`
  and `ops/entity-registry.json` there is.
- **A second collision rule.** `birth._refuse_collisions` asks the registry through `normalize`,
  over all three identity inputs (id, name, every alias). A caller comparing strings itself is a
  second registry with a different opinion.
- **Reading `ops/entity-registry.json` to answer "does this name resolve".** That is
  `kernel.registry`'s `canonical_id`, through the registry this package derives — the file is a
  derived view, and a reader parsing it a second way is a second parser.

## Data & contracts

- **The page is the source of truth**; `ops/entity-registry.json` is derived from it, and the
  index's snapshot of that file is derived again. A hand-edit to either lower layer is drift, and
  `compare` is what names it.
- **`approved_by:` is present and non-empty on every entity page the librarian writes.** A page
  with no such key at all predates the field and reads the same way — as an identity nobody in
  particular introduced, never as one waiting on somebody.
- `ENTITY_TYPES` is the closed list a birth is validated against, and the same list the console's
  Register form offers. It lives here because the page's `entity_type:` is what it constrains.

## Tests

`tests/entities/` — the birth gate's refusals and their benign twins, the generator's drift
comparison, and the knowledge-repo linter's own unit tests (`test_stigmergy_lint.py`, run against
the frozen copy). The birth path end to end, through a real commit, is
`tests/librarian/test_identity_unit.py` and `tests/librarian/test_processing_pg.py` — this package
has no door of its own to test.
