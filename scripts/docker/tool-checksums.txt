# SHA-256 of every third-party binary the image downloads, in `sha256sum -c` format.
#
# The Dockerfile fetches exactly the two archives its build architecture needs and verifies them
# against this file with `sha256sum --ignore-missing -c` — which fails when a downloaded archive
# does not match, and also when NOTHING was verified (coreutils exits non-zero if no listed file
# was present, so a silently-skipped download cannot pass).
#
# Both architectures are listed because the image is built in two places: linux/amd64 for Fly, and
# whatever `docker compose build` is running on for the librarian e2e (an arm64 Mac, today).
#
# The Claude Code CLI is here for the same reason and was NOT, which was the asymmetry: it was
# version-pinned and installed straight from the npm registry, so a rebuild trusted whatever bytes
# the registry served for that version while the two binaries beside it were digest-verified. A
# version pin says WHICH release; a digest says which BYTES. Its npm tarball is a ~13KB
# platform-independent wrapper, so ONE line covers every architecture — the ~500MB native binary it
# places comes from a per-platform optional dependency, which npm still verifies against the
# registry's own integrity metadata and this file does not yet pin (named as a residual in the
# Dockerfile rather than left to be discovered).
#
# To bump a version: change it in the Dockerfile's ARG, then replace the line(s) here from upstream —
#   gitleaks:    https://github.com/gitleaks/gitleaks/releases/download/v<V>/gitleaks_<V>_checksums.txt
#   node:        https://nodejs.org/dist/v<V>/SHASUMS256.txt
#   claude-code: npm view @anthropic-ai/claude-code@<V> dist.tarball   (then sha256sum the download)
# Never hand-edit a digest: the point of the file is that nobody can.
